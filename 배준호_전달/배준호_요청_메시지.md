## 1. 배경 — 무엇을 확인했나

9/28에 4가지 구성(정상 / 이음부 단차 / 수직 변형 / 좌우 높이차) × 6회 = 24회 주행 데이터를 얻었습니다. 이걸 현재 서버의 `rail_defect.py`에 재생해 봤더니 결함이 하나도 표시되지 않았습니다. 원인은 두 가지였습니다.

1. `_pair_is_fresh` / `_point_from_pair`에서 좌·우 엔코더 위치 차가 80 mm(`POSITION_MATCH_MM`)를 넘으면 샘플을 버리는데, 실제 주행에서는 좌·우 엔코더가 최대 29%까지 다르게 세서(구동륜 미끄러짐) 350 mm쯤부터 모든 샘플이 버려지고 있었습니다.
2. 이걸 고쳐도 구간 단위 규칙으로는 이음부 단차만 잡히고 수직 변형·좌우 높이차는 안 잡혔습니다. 센서가 앞뒤 바퀴 가운데 있어서 완만한 처짐은 이음부 자리에서 0.4 mm 봉우리로만 나타나기 때문에(현측정 원리), 순간값 비교로는 원리적으로 못 잡습니다.

그래서 주행이 끝날 때마다 전체 파형에 이론 파형을 맞추는 방식(`pass_analysis.py`)을 만들어 엔진에 붙였고, 정상 6회를 기준선으로 등록한 뒤 나머지 18회를 재생하니 18/18 판별, 단계도 단차 위험·수직 위험·좌우 주의로 설계 의도와 같게 나왔습니다.

## 3. 서버에 해 주실 것

### 3-1. 파일 교체
`rail_defect.py` 교체, `pass_analysis.py` 추가. 의존성은 numpy뿐입니다.

### 3-2. `main.py`에 엔드포인트 2개 추가

```python
@app.post("/api/baseline_mode")
async def set_baseline_mode(body: dict):
    defect_engine.baseline_mode = bool(body.get("enabled", False))
    return {"baseline_mode": defect_engine.baseline_mode,
            "baseline_passes": defect_engine.pass_analyzer.baseline_count}

@app.post("/api/finish_pass")
async def finish_pass():
    return {"result": defect_engine.finish_pass()}
```

- `baseline_mode`를 켜고 정상 레일을 3회 이상 달린 뒤 끄면 기준선이 등록됩니다. `rail_baseline.json`(환경변수 `RAIL_BASELINE_FILE`로 경로 변경 가능)에 저장되어 서버를 재시작해도 유지됩니다.
- `finish_pass`는 대차가 출발점으로 되돌아가지 않는 운영일 때만 필요합니다. 위치가 200 mm 이상 되돌아가면 엔진이 자동으로 주행 종료 처리합니다.

### 3-3. 프론트(`index.html`)에 주행 분석 결과 표시
스냅샷(dict)에 `pass_result`, `baseline_mode`, `baseline_passes` 키가 추가됐습니다. `defects` 목록에서 `"source": "pass_fit"`인 항목이 주행 분석 결과이고, 필드는 다음과 같습니다.

| 필드 | 뜻 |
|---|---|
| `defect_type` | normal / joint_step / vertical / cross_level |
| `stage` | ok / caution / danger (3회 미만이면 항상 ok) |
| `magnitude_mm` | 최근 3회 평균 크기 |
| `sizes_mm` | {HF, C, E} 이번 주행의 세 성분 |
| `side` | cross_level일 때 낮은 쪽 (left/right) |
| `from_mm`, `to_mm` | 결함 구간 |
| `passes_used` | 평균에 쓰인 주행 횟수 |

`rail_risk_left` / `rail_risk_right` 배열은 그대로이고, 주행 분석 결과가 있으면 그 결과로 채워집니다. 그래서 Unity 쪽(`RailTwinController.ApplyState`)은 손댈 것이 없습니다.

`대처지침_웹표시용.md`의 표를 그대로 웹에 올려 주시고, 결함 항목마다 위치·분류·크기·단계·조치 문구가 한 줄로 보이게 해 주시면 됩니다.

### 3-4. 한계선과 판정 규칙 (이미 코드에 들어 있음, 참고)
- 한계선 `LIMIT_MM`: 이음부 단차 1.0 / 수직 변형 1.0 / 좌우 높이차 5 mm — ISO 12488-1 1급(항만 갠트리) 공차
- 단계: 정상 ≤ 50%, 주의 50%~한계선, 위험 > 한계선
- 단계 판정은 같은 구간을 3회 이상 지난 평균값으로만 (`MIN_PASSES_FOR_STAGE = 3`). 1회 값으로 판정하면 정상 레일 6회 중 2회가 주의로 오판되어서 이렇게 정했습니다.
- 임시값이던 0.8 / 2.0 / 10은 없앴습니다.

### 3-5. 검증 방법
적용 후 `python replay_csv.py 레일측정데이터` 를 돌려서 마지막에 `판별 정답 18/18`이 나오면 정상입니다. 정상 6회가 기준선으로 등록되고, 단차 6회 danger, 수직 6회 danger, 좌우 6회 caution(left)이 나와야 합니다.
