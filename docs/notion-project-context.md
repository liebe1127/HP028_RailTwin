## 2. 프로젝트 정의

본 프로젝트는 대형 갠트리 크레인이 하부 주행 레일을 따라 이동할 때 발생하는 동적 진동·가속도·자이로·거리 데이터를 수집하고, 간격·기울기 규칙으로 레일의 이상 구간을 찾아 웹 대시보드와 Unity WebGL에 표시하는 디지털 트윈 안전관리 시스템이다.

핵심 결과는 다음과 같다.

- 주행 중 센서 데이터 수집
- 정지 노이즈를 줄이는 엣지 임계값 처리
- LR18 좌·우 간격, MPU 충격·기울기, 엔코더 위치로 네 분류를 규칙 판정한다. 정상 / 이음부 단차 / 수직 변형 / 좌우 높이차
- 크기와 변화 속도로 정상·주의·위험 세 단계와 평속·감속·정지를 정한다
- InfluxDB 시계열 저장과 WebSocket 실시간 전송
- 웹 대시보드와 Unity WebGL(레일만)의 위치·이상 구간 시각화

상부 구조물의 변형은 핵심 예측 대상이 아니다. PyTorch RBF 추론은 2026-09-16 이후 목표 스택에서 제외한다.

## 3. 전체 시스템 구조

### 센서·엣지

- 현재 MCU: ESP32-S3-DevKitC-1 N16R8 1장. 좌·우를 I2C 두 버스로 함께 본다
- 좌·우 각 1개: MPU-6050, ADS1115, GTRIC LR18-08U, L298N, JGB37-520(내장 엔코더), MT3608
- 브링업은 가속도·레일 간격·엔코더 위치를 읽는다. 자이로는 읽지 않는다
- 정지 잡음은 약 0.001–0.002V이다. 기준값은 켠 뒤 출력이 내려앉은 다음 잡는다

### 백엔드·스트림

- Python, FastAPI, 비동기 Queue, MQTT 구독, WebSocket 다운링크
- InfluxDB 및 Flux 기반 시계열 저장·조회
- 저장소의 이전 C3 펌웨어 계약은 MQTT QoS 1로 NCP Mosquitto에 발행하고 FastAPI가 구독한다. 조립된 S3 브링업은 USB 시리얼이며 이 MQTT 경로로 전송하지 않는다.
- 센서 미연결 시에도 전체 파이프라인을 검증할 수 있도록 더미 스트리머를 사용한다.

### AI·신호 처리

- 2026-09 배용진 확정안: 구간 특징 `m`, `Δ`, `dm/dx`, `dΔ/dx`, `apeak`, `φ`로 네 분류를 가른다. RBF·웨이블릿·파고율은 쓰지 않는다.
- `defect_type`은 `joint_step` / `vertical` / `cross_level`이다. 정상 구간은 목록에 넣지 않는다.
- 단계는 `ok` / `caution` / `danger`이다. 한계선은 2026-09-29 배용진 확정으로 ISO 12488-1 1급이다. 이음부 단차 1.0 mm, 수직 변형 1.0 mm, 좌우 높이차 5 mm. 단계는 같은 구간 3회 평균부터 낸다. 주행이 끝나면 `pass_analysis.py` 파형 적합이 구간 규칙보다 우선한다. 표 6·표 7은 원문 확인 전이다.
- 0.1mm 정밀도는 같은 구간을 6회 이상 평균할 때의 목표다. 한 번 측정의 제조사 반복정밀도는 약 ±0.24mm로 본다.

### 시각화

- 웹 대시보드에서 센서값, 간격 편차, 롤, 이상 구간, 장치·서버 상태를 표시한다.
- Unity WebGL에서 좌·우 레일만 띄우고 구간 색과 갠트리 위치를 표시한다. 크레인 메시는 넣지 않는다.
- 레일 구간 색상은 정상에서 이상으로 갈수록 파랑–초록–노랑–빨강 계열로 변화한다.

## 4. 현재 센서 모듈

세부 핀·교정표·미확인 항목은 `docs/hardware-configuration-history.md`가 기준이다.

### 확정된 구성 (2026-09-24 조립 실물)

- MCU 1장: ESP32-S3-DevKitC-1 N16R8
- 좌 버스 `Wire` GPIO11/12, 우 버스 `Wire1` GPIO13/14. 각 버스 ADS1115 `0x48`, MPU-6050 `0x68`
- GTRIC LR18-08U 2개. 0–10V를 20kΩ/10kΩ으로 나눠 ADS1115 AIN0에 연결. `DIV = 3.0`
- L298N 2개(A채널, ENA 점퍼 제거), JGB37-520 2개(내장 엔코더, A상 상승 에지)
- MT3608 2개. 센서 전원 목표 24V
- 18650 9개. 로직 1셀은 USB-C로 보드에 공급. 센서 좌·우 1셀, 모터 좌·우 3S. 접지만 공통
- 거리 교정표(0/2/4/6/8mm)와 설치 목표 5.00mm, 엔코더 약 0.0497 mm/카운트는 브링업에 들어 있다
- 100nF는 미장착. 저항 Ω, 전원 전압, 레일 0mm, IMU X·Y 방향, 코드 좌우와 진행 방향의 일치는 미확인

2026-08-23 몸체 라벨은 LR18-08U, DC 15–30V, 0–10V, 1–8mm, 갈색(+), 청색(−), 흑색(출력)이다.

`rail-left-01` / `rail-right-01`는 좌·우 스트림 이름이다. 조립 보드에 올리는 스케치는 `firmware/esp32_s3_rail_node/`이다.

### 취소된 초기 프로토타입

다음 조합은 초기 데이터 수집 검증용이었으며 현재 사용하지 않는다. 현재 MCU도 ESP32-S3 계열이지만 보드와 센서가 다르다.

- ESP32-S3-WROOM-1 + ADXL345 + HC-SR04
- 그 스케치는 2026-09-27에 저장소에서 삭제했다.

현재 설계, 배선, 펌웨어, 부품 목록, 보고서의 최종 하드웨어로 인용하지 않는다.

### 현재 필요한 작업

- 레일·바닥 0mm와 이음부 위치·단차 높이(좌·우)
- `t` 1회 주행의 줄자 거리와 `COUNTS_PER_300` 대조
- 코드의 좌·우, 전진 방향, GY-521 X·Y 화살표
- 분압 저항 Ω과 전원 전압은 값이 이상할 때 측정
- 저장소 C3 MQTT 펌웨어를 이 보드에 그대로 올리지 않는다. S3 핀맵으로 다시 맞춘 뒤에 업로드한다

## 5. 물리 모형과 3D 모델

### 기준 모델

- 참조 대상은 부산 신항의 HD현대삼호 RMG 계열 갠트리 크레인이다.
- 제조사 관련 자료에는 한진중공업이 기록되어 있다.
- 디지털 시각화용으로 DGCRANE의 레일 포함 Double Girder Gantry Crane 모델을 선정했다.
- 구매한 상용 모델과 포함 자산은 라이선스 문제로 공개 저장소에 올리면 안 된다.

### 디지털 모델과 물리 모형의 구분

- 구매한 상용 모델은 디지털 트윈 시각화 트랙이다.
- 실제 제작 모형은 Blender에서 단순화한 평판·하드보드 구조 트랙이다.
- 두 모델은 목적과 물리 스케일이 다르므로 동일 모델처럼 서술하지 않는다.
- 과거 문서에는 Unity·FBX 권장이 있으나 실제 프론트엔드는 Godot를 사용한다. 이는 초기 기술 검토 기록이다.

### 물리 모형 구조

- 전체 모형은 약 1.4m급으로 계획되었다.
- 강도가 약한 판재를 고려해 약 5T 두께를 기준으로 재설계했다.
- 이동과 보관을 위해 분해·재조립하는 구조를 고려했다.
- 주요 평판 부품:
  - UpperConnectingBeam 2개
  - GantryLeg 4개
  - GroundBeam 2개
  - MainBeam 2개
- 조립 메커니즘과 최종 설치 장소는 추가 확정이 필요하다.

### 치수 변경 이력

- 초기 바퀴 지름은 약 7cm였다.
- 중간 검토 과정에서 8cm와 7cm가 혼재했다.
- 2026-09-24 구동륜 도면은 답면 지름 47mm, 플랜지 외경 53mm, 폭 18mm, 둘레 147.7mm다. 출력품 실측은 미확인이다. 예전 문서의 5.3cm는 플랜지 외경과 같다.
- 과거 7cm 기준 도면·화면 치수는 대략 `×0.771` 보정이 필요하다.
- 첨부된 Blender 캡처의 치수는 선택 지점 간 거리일 수 있으므로 제작 확정 치수로 바로 사용하지 않는다.

### 구동부

구동부는 모터·바퀴·배선·센서 모듈을 결합하는 하부 주행 장치다. 2026-09-25 실물은 알루미늄 프로파일 대차 위에 브레드보드·전지·배선을 올리고, 양 끝은 JGB37-520과 3D 출력 바퀴이다. 3D 출력 외피 안에 ESP32-C3를 넣는 안은 이전 수납 방향이다.

보유 STL:

- `L_FRONT3_SCALED_1.35.stl`
- `R_FRONT3_SCALED_1.35.stl`
- `L_REAR3_SCALED_1.35.stl`
- `R_REAR3_SCALED_1.35.stl`
- `wheel_drive_cylinder.stl`
- `wheel_idle_cylinder.stl`
- `idle_bracket_v6.stl`

관련 DXF:

- `FrontMotorpart.dxf`
- `BackMotorPart.dxf`
- Blender와 DXF의 단위가 m로 기록되어 있어 CAD 이관 시 단위를 확인해야 한다.

출력 관련 기록:

- 완성 형상은 한 방향에서 약 14시간 16분, 회전 배치에서 약 11시간 34분으로 예상되었다.
- 실제 출력은 예측보다 길어질 수 있다.
- 얇은 판, 모터까지 포함된 형상, 서포트 제거, 조립 상태 출력이 주요 위험이다.
- 약 30% 축소한 10cm급 테스트 출력이 수행되었다.
- STL의 정확한 벽 두께, 내부 수납 공간, 공차와 부품 간섭은 별도 형상 검증이 필요하다.

### 레일 재료

- 실제 H형 강철 레일을 축소 모형에 그대로 적용하기는 어렵다.
- 2026-09-24 측정 레일은 바닥에 놓은 아연 각파이프이다. 고정이 없고, 이음 연결부 3D 출력은 3개이며 나머지는 테이프이다. 알루미늄 프로파일은 대차 프레임이다.
- 대차 실물 사진: `docs/hardware-digital-twin/photos/assembled/` (01–07). 파일별 설명은 `docs/hardware-digital-twin/README.md`. 07이 아연 각파이프 두 줄 위의 대차다. 은색 프로파일은 프레임이고 측정 레일이 아니다.
- 이음부 단차의 정답값은 절단 오차를 잰 실측이다. 0.5/1.0/2.0mm는 이 레일의 설계 정답이 아니다. 수직 변형 경사판과 한쪽만 높인 판은 제작 여부가 미확인이다.
- 단면·간격·길이·파이프 수는 미확인이다. SUS304·플라스틱·퍼티·PLA·테이프는 유도형 센서가 약하거나 보지 못한다. 결함 크기는 모형 축척으로 줄이지 않는다. 레일을 옆으로 미는 시험은 판정 밖이다.

## 6. 데이터 계약과 시연

아래 필드는 저장소의 이전 ESP32-C3 MQTT 계약이다. 조립된 S3 브링업의 시리얼 출력과 같지 않다.

- 계약: `type`, `schema_version`
- 장치·레일: `device_id`, `rail_side`, `firmware_version`
- 전송 추적: `batch_seq`, `sample_seq`, `uptime_us`, `dropped_batches`
- 위치: `position_mm`
- LR18 계측: `sensor_distance_mm`, `adc_raw`, `adc_voltage_v`, `sensor_voltage_v`
- MPU6050: `accel_mps2[3]`, `gyro_radps[3]`

서버는 좌·우를 한 구간으로 묶어 다음 필드를 웹·Unity에 전송한다.

- 시간: `ts`
- 시각화 위치: `distance_x`(cm, `position_mm`에서 변환)
- 분류·단계: `defect_type`, `stage`, `motion`
- 근거: `m_mm`, `delta_mm`, `dm_dx`, `ddelta_dx`, `apeak`, `tilt_deg`
- 추세: `remaining_s`, `rate_mm_per_s`, `pass_count`, `relative_fast`
- 구간 색: `rail_risk` (0 정상, 0.6 주의, 1 위험)
- 레일 길이·구간: `rail_length_cm`, `segment_count`

과거 `AAX`·`DIST`·`MAX` 계열은 취소된 ESP32-S3·ADXL345·HC-SR04 프로토타입 계약이며 활성 수집 경로에서 제거했다. 좌·우 레일은 `rail_side`와 화면 WebSocket의 `left`·`right` 객체로 구분한다.

더미 스트리머는 약 1m 레일에서 20~25cm 이음부 단차, 45~70cm 수직 변형, 80~90cm 좌우 높이차를 만든다. 랩이 반복되면 크기가 커져 추세 계산을 보여 준다. 화면에는 시뮬레이션이라고 적으며, 정확도 근거가 아니다.

## 7. 특징과 판정

1. 주행 중 좌·우 간격, 세로 가속도, 기울기, 위치를 모은다
2. 약 50mm 구간마다 `m`, `Δ`, `dm/dx`, `dΔ/dx`, `apeak`, `φ`를 계산한다
3. 이음부 단차, 수직 변형, 좌우 높이차를 규칙으로 가른다
4. ISO 한계선 대비 비율로 정상·주의·위험을 정하고, 시점 3개 이상이면 남은 시간을 계산한다
5. 주의 구간은 감속, 위험 구간은 진입 전에 정지한다

실측 왕복과 가속 열화(금속판을 한 장씩 추가해 다섯 시점)는 아직 하지 않았다. 더미 추세는 넣은 값을 되찾는 시뮬레이션이다.

### 주의할 점

- Notion의 완료 상태와 실제 시연 성공 여부를 구분해야 한다.
- HTTPS 페이지에서 암호화되지 않은 WebSocket 연결이 차단된 이력이 있다.
- WSS 구성이 문서상 완료로 표시된 부분이 있어도 실제 운영 주소와 인증서 상태를 다시 검증해야 한다.
- 보고서에는 검증한 시점과 환경을 함께 적고, 미검증 상태를 완료라고 단정하지 않는다.

## 9. 프론트엔드와 디지털 트윈

- 실제 시각화 엔진은 Unity WebGL(레일만)이다. Godot 스크립트는 이력으로 남는다.
- `distance_x`를 이용해 크레인 위치를 이동시킨다.
- `rail_risk` 0 / 0.6 / 1 로 정상·주의·위험 색을 갱신한다.
- 과거 데모에서는 `CREST > 1.3`일 때 센서 위치에 빨간 점을 표시했다.
- `rail_length_cm`과 `segment_count`는 초기 데모에서 하드코딩된 값이었다.
- 과거에는 `rail_risk`가 전부 1인 데모 데이터가 있어 색 변화 검증에 한계가 있었다.
- 웹용 차트 애드온은 호환 문제로 제거된 기록이 있으며 Raw 데이터 표시가 사용되었다.
- 멀티플랫폼, 시각화 옵션 다양화, 메모리 누수 해결 작업이 진행 항목으로 기록되어 있다.

## 11. 개발보고서 작성 원칙

### 반드시 지킬 내용

- 핵심 대상은 하부 주행 레일의 이음부 단차, 수직 변형, 좌우 높이차다.
- 원시 간격·가속도를 구간 특징 여섯 개로 만든 뒤 규칙으로 판정한다. RBF·웨이블릿·파고율을 현재 방법으로 쓰지 않는다.
- 현재 센서 구성과 취소된 초기 프로토타입을 섞지 않는다.
- 구동부는 알루미늄 프로파일 대차와 그 위 브레드보드·전지로 설명한다. 측정 레일은 아연 각파이프이다.
- 합성 데이터 결과와 실측 데이터 결과를 명확히 구분한다.
- 구현 완료, 계획, 백로그, 검증 필요 상태를 구분한다.
- 구매한 3D 자산의 라이선스와 공개 제한을 고려한다.

### 근거 없이 단정하면 안 되는 내용

- 실제 현장 정확도와 사고 예방 효과의 정량 수치
- 분압 저항의 Ω 실측, 100nF 미장착, 전원 전압 실측을 확정값처럼 쓰기
- STL의 수납·조립·공차 검증 완료
- 실제 WSS 운영 연결 성공
- 이음부 단차의 위치·높이를 설계값 0.5/1.0/2.0mm로 단정
- 저장소 C3 MQTT 펌웨어가 조립된 S3에서 동작한다고 단정
- 장기간 실측 데이터로 학습 완료

## 12. 현재 주요 리스크와 후속 작업

1. 레일 0mm, 이음부 위치·높이, `t` 주행의 줄자 거리, 진행 방향의 좌·우와 전진, IMU 축 사진을 남긴다.
2. 분압 저항 Ω과 센서·모터·로직 전압은 이상이 있을 때 측정한다. 거리 교정표는 가변저항을 돌리거나 레일 재질이 다를 때 다시 뜬다.
3. 대차는 조립되어 있다. 레일은 고정되지 않으므로 반복 주행 전후로 단차와 간격을 다시 잰다.
4. 이음부 단차는 아연 각파이프 절단 오차의 실측이다. 수직 변형 경사판과 한쪽 높임 판의 제작 여부는 미확인이다. 반복 주행 실측은 아직이다.
5. 실제 주행 데이터를 수집하고 라벨링해야 한다.
6. 합성 데이터 모델을 실측 데이터로 재학습·평가해야 한다.
7. 백엔드와 Godot의 WSS 실연동을 다시 검증해야 한다.
8. 서버 MQTT 계약은 아직 C3 두 노드용이다. S3 한 장이 좌·우를 어떻게 보낼지는 펌웨어를 다시 맞출 때 정한다.
9. 조립 완료 모형의 반복 시운전 절차를 작성하고 시험해야 한다.
10. 최종 보고서의 진행률과 성능 수치는 증빙 자료와 함께 갱신해야 한다.
