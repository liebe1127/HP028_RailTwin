## 2. 프로젝트 정의

본 프로젝트는 대형 갠트리 크레인이 하부 주행 레일을 따라 이동할 때 발생하는 동적 진동·가속도·자이로·거리 데이터를 수집하고, 특징 공학과 AI 모델을 이용해 레일의 단차·국부적인 침하·뒤틀림과 같은 기하 이상을 예측·감지하는 디지털 트윈 안전관리 시스템이다.

핵심 결과는 다음과 같다.

- 주행 중 센서 데이터 수집
- 정지 노이즈를 줄이는 엣지 임계값 처리
- 웨이블릿 디노이징과 파고율 등 특징 공학
- PyTorch RBF 대리 모델 기반 레일 변형 위험 추론
- InfluxDB 시계열 저장과 WebSocket 실시간 전송
- 웹 대시보드와 Godot 3D 디지털 트윈의 위치·위험도 시각화

상부 구조물의 변형은 핵심 예측 대상이 아니다.

## 3. 전체 시스템 구조

### 센서·엣지

- 현재 MCU: ESP32-C3 Mini
- 현재 관성 센서: MPU-6050
- 현재 외부 ADC: ADS1115
- 현재 거리 계측 센서: GTRIC LR18-08U M18 아날로그 유도형 근접 센서
- 주행 시 동적 가속도·자이로·레일과의 거리 변화를 계측한다.
- 정지 상태에서 발생하는 미세 노이즈는 엣지 임계값으로 걸러 불필요한 전송을 줄이는 방향이다.

### 백엔드·스트림

- Python, FastAPI, 비동기 Queue, WebSocket
- InfluxDB 및 Flux 기반 시계열 저장·조회
- Redis Stream과 MQTT는 무선·다중 장치 확장 단계의 계획 기술이다.
- 센서 미연결 시에도 전체 파이프라인을 검증할 수 있도록 더미 스트리머를 사용한다.

### AI·신호 처리

- 원시 센서값을 모델에 바로 입력하지 않는다.
- 이동평균, 웨이블릿 디노이징, 파고율(Crest Factor) 등 특징 공학을 거친다.
- PyTorch 기반 RBF(Radial Basis Function) 대리 모델을 사용한다.
- 현재 합성 데이터 기반 모델은 파이프라인 검증용이며 실제 레일 상태 정확도를 입증한 모델로 표현하면 안 된다.

### 시각화

- 웹 대시보드에서 센서값, 파고율, 예측값, 장치·서버 상태를 표시한다.
- Godot 기반 3D 디지털 트윈에서 크레인 위치와 좌·우 레일 구간별 위험도를 색상으로 표현한다.
- 레일 구간 색상은 정상에서 위험으로 갈수록 파랑–초록–노랑–빨강 계열로 변화한다.

## 4. 현재 센서 모듈

### 확정된 구성

- ESP32-C3 Mini
- MPU-6050 6축 가속도·자이로 센서
- ADS1115 16bit 4채널 ADC
- GTRIC LR18-08U M18 아날로그 유도형 근접 센서
- 18650 배터리 및 배터리 홀더
- MT3608 계열 승압 모듈
- 브레드보드, 점퍼선 및 전원 배선

GTRIC 센서는 금속 레일과 센서 사이 간격의 변화를 연속값으로 계측한다. 2026-08-23 실제 보유품 몸체 라벨 사진으로 모델 LR18-08U, DC 15–30V 동작 전압, 0–10V 출력 전압, 1–8mm 감지 거리를 확인했다. 라벨 배선도는 갈색 전원(+), 청색 전원(-), 흑색 아날로그 출력을 나타낸다.

- 0–10V 출력을 ADS1115 입력 허용 범위에 맞추는 분압·입력 보호 회로가 필요하다.
- 센서와 ADC의 공통 접지, 분압비와 보호소자를 회로 제작 전에 확정해야 한다.
- 승압 모듈의 실제 출력 전압·전류 용량을 멀티미터로 검증해야 한다.

2026-08-23 사용자 제공 실물 사진에서 ESP32-C3 Mini, MPU-6050, ADS1115, 전원부, 18650 배터리, GTRIC LR18-08U가 함께 배선된 센서 모듈을 확인했다. 사용자 확인에 따르면 ADS1115용 분압·보호 회로도 포함되어 있다. 이 사진은 부품 배치와 배선 진행의 증빙으로 사용할 수 있으나, 저항값·보호소자 정격·실제 분압비와 데이터 수신 성공은 측정 로그로 추가 검증해야 한다.

## 5. 물리 모형과 3D 모델

### 기준 모델

- 참조 대상은 부산 신항의 HD현대삼호 RMG 계열 갠트리 크레인이다.
- 제조사 관련 자료에는 한진중공업이 기록되어 있다.
- 디지털 시각화용으로 DGCRANE의 레일 포함 Double Girder Gantry Crane 모델을 선정했다.
- 구매한 상용 모델과 포함 자산은 라이선스 문제로 공개 저장소에 올리면 안 된다.

### 디지털 모델과 물리 모형의 구분

- 구매한 상용 모델은 디지털 트윈 시각화 트랙이다.
- 실제 제작 모형은 Blender에서 단순화한 평판·하드보드 구조 트랙이다.
- 두 모델은 목적과 물리 스케일이 다르므로 동일 모델처럼 서술하지 않는다.
- 과거 문서에는 Unity·FBX 권장이 있으나 실제 프론트엔드는 Godot를 사용한다. 이는 초기 기술 검토 기록이다.

### 물리 모형 구조

- 전체 모형은 약 1.4m급으로 계획되었다.
- 강도가 약한 판재를 고려해 약 5T 두께를 기준으로 재설계했다.
- 이동과 보관을 위해 분해·재조립하는 구조를 고려했다.
- 주요 평판 부품:
  - UpperConnectingBeam 2개
  - GantryLeg 4개
  - GroundBeam 2개
  - MainBeam 2개
- 조립 메커니즘과 최종 설치 장소는 추가 확정이 필요하다.

### 치수 변경 이력

- 초기 바퀴 지름은 약 7cm였다.
- 중간 검토 과정에서 8cm와 7cm가 혼재했다.
- 2026-08-07 이후 최신 기준 바퀴 지름은 5.3cm다.
- 과거 7cm 기준 도면·화면 치수는 대략 `×0.771` 보정이 필요하다.
- 첨부된 Blender 캡처의 치수는 선택 지점 간 거리일 수 있으므로 제작 확정 치수로 바로 사용하지 않는다.

### 구동부

구동부는 모터·바퀴·배선·센서 모듈을 결합하는 하부 주행 장치다. 3D 출력 외피 안에 ESP32-C3 Mini와 센서 모듈을 넣는 방향이다.

보유 STL:

- `L_FRONT3_SCALED_1.35.stl`
- `R_FRONT3_SCALED_1.35.stl`
- `L_REAR3_SCALED_1.35.stl`
- `R_REAR3_SCALED_1.35.stl`
- `wheel_drive_cylinder.stl`
- `wheel_idle_cylinder.stl`
- `idle_bracket_v6.stl`

관련 DXF:

- `FrontMotorpart.dxf`
- `BackMotorPart.dxf`
- Blender와 DXF의 단위가 m로 기록되어 있어 CAD 이관 시 단위를 확인해야 한다.

출력 관련 기록:

- 완성 형상은 한 방향에서 약 14시간 16분, 회전 배치에서 약 11시간 34분으로 예상되었다.
- 실제 출력은 예측보다 길어질 수 있다.
- 얇은 판, 모터까지 포함된 형상, 서포트 제거, 조립 상태 출력이 주요 위험이다.
- 약 30% 축소한 10cm급 테스트 출력이 수행되었다.
- STL의 정확한 벽 두께, 내부 수납 공간, 공차와 부품 간섭은 별도 형상 검증이 필요하다.

### 레일 재료

- 실제 H형 강철 레일을 축소 모형에 그대로 적용하기는 어렵다.
- 알루미늄 프로파일, 수납장·창틀 레일, 스틸 바, 가공 판재 등이 후보로 검토되었다.
- 최종 재료, 길이, 단차·침하·뒤틀림 재현 방법은 확정되지 않았다.

## 6. 데이터 계약과 시연

현재 ESP32-C3 센서 업링크의 주요 필드는 다음과 같다.

- 계약: `type`, `schema_version`
- 장치·레일: `device_id`, `rail_side`, `firmware_version`
- 전송 추적: `batch_seq`, `sample_seq`, `uptime_us`, `dropped_batches`
- 위치: `position_mm`
- LR18 계측: `sensor_distance_mm`, `adc_raw`, `adc_voltage_v`, `sensor_voltage_v`
- MPU6050: `accel_mps2[3]`, `gyro_radps[3]`

서버는 이를 정규화·특징 공학한 뒤 다음 필드를 웹·Godot에 전송한다.

- 시간: `ts`
- 시각화 위치: `distance_x`(cm, `position_mm`에서 변환)
- 파고율: `CREST`
- 예측값: `PRED_RAIL_DEFORM`
- 구간별 위험도: `rail_risk`
- 레일 길이·구간: `rail_length_cm`, `segment_count`
- 현재 센서 진단값과 장치·전송 추적 필드

과거 `AAX`·`DIST`·`MAX` 계열은 취소된 ESP32-S3·ADXL345·HC-SR04 프로토타입 계약이며 활성 수집 경로에서 제거했다. 좌·우 레일은 `rail_side`와 WebSocket의 `left`·`right` 객체로 구분한다.

더미 스트리머는 약 1m 레일의 40~50cm 구간에서 단차 충격을 모사한다. 이는 기능 시연용 합성 신호이며 실측 성능 근거가 아니다.

## 7. 특징 공학과 AI

### 처리 방향

1. 주행 중 동적 센서 데이터 수집
2. 정지 노이즈 억제
3. 롤링 윈도우 구성
4. 웨이블릿 기반 노이즈 완화
5. 파고율 등 충격 특징 추출
6. 정규화된 특징을 RBF 모델에 입력
7. 레일 변형 예측값과 구간 위험도 생성

### 현재 성숙도

- RBF 구조와 합성 데이터 학습 파이프라인은 구현되어 있다.
- 합성 데이터는 SILS와 데이터 흐름 검증에 사용한다.
- 실제 정상·단차·침하·뒤틀림 데이터셋과 실측 라벨은 충분하지 않다.
- 실제 성능을 주장하려면 MAE, RMSE, 재현율, 오탐률, 추론 지연시간 등을 실측 데이터로 평가해야 한다.
- 하이퍼파라미터 최적화와 다양한 판단 방법 작업은 Notion에서 계획·백로그 수준이다.

## 8. 백엔드와 배포

### 구현·계획

- FastAPI 기반 실시간 서버
- 비동기 Producer–Queue–Consumer 구조
- WebSocket 브로드캐스트
- InfluxDB 저장

- Redis와 MQTT는 확장 계획
- Docker 및 클라우드 배포 구성이 저장소에 존재한다.

### 주의할 점

- Notion의 완료 상태와 실제 시연 성공 여부를 구분해야 한다.
- HTTPS 페이지에서 암호화되지 않은 WebSocket 연결이 차단된 이력이 있다.
- WSS 구성이 문서상 완료로 표시된 부분이 있어도 실제 운영 주소와 인증서 상태를 다시 검증해야 한다.
- 보고서에는 검증한 시점과 환경을 함께 적고, 미검증 상태를 완료라고 단정하지 않는다.

## 9. 프론트엔드와 디지털 트윈

- 실제 시각화 엔진은 Godot다.
- `distance_x`를 이용해 크레인 위치를 이동시킨다.
- `rail_risk`를 이용해 레일 세그먼트의 색상을 갱신한다.
- 과거 데모에서는 `CREST > 1.3`일 때 센서 위치에 빨간 점을 표시했다.
- `rail_length_cm`과 `segment_count`는 초기 데모에서 하드코딩된 값이었다.
- 과거에는 `rail_risk`가 전부 1인 데모 데이터가 있어 색 변화 검증에 한계가 있었다.
- 웹용 차트 애드온은 호환 문제로 제거된 기록이 있으며 Raw 데이터 표시가 사용되었다.
- 멀티플랫폼, 시각화 옵션 다양화, 메모리 누수 해결 작업이 진행 항목으로 기록되어 있다.

## 11. 개발보고서 작성 원칙

### 반드시 지킬 내용

- 핵심 대상은 하부 주행 레일의 단차·침하·뒤틀림이다.
- 현재 센서 구성과 취소된 초기 프로토타입을 섞지 않는다.
- 구동부 외피 내부에 현재 센서 모듈을 결합하는 물리 구조를 설명한다.
- 원시 데이터가 아니라 특징 공학을 거쳐 AI에 입력한다.
- 합성 데이터 결과와 실측 데이터 결과를 명확히 구분한다.
- 구현 완료, 계획, 백로그, 검증 필요 상태를 구분한다.
- 구매한 3D 자산의 라이선스와 공개 제한을 고려한다.

### 근거 없이 단정하면 안 되는 내용

- 실제 현장 정확도와 사고 예방 효과의 정량 수치
- 최종 ADS1115 분압비·보호소자와 확정 회로
- STL의 수납·조립·공차 검증 완료
- 실제 WSS 운영 연결 성공
- 실제 레일 재료와 이상 재현 방식 확정
- 현재 하드웨어 펌웨어의 실물 보드 컴파일·실행 로그와 반복 계측 검증
- 장기간 실측 데이터로 학습 완료

## 12. 현재 주요 리스크와 후속 작업

1. 저장소에 반영한 ESP32-C3 WiFi WebSocket 펌웨어를 실물 보드에 업로드하고 실행 로그와 반복 계측으로 검증해야 한다.
2. GTRIC LR18-08U 전원 출력과 0–10V용 ADS1115 분압·보호 회로의 실제 전압·회로값을 검증해야 한다.
3. 구동부 내부 수납 공간, 벽 두께, 조립 공차를 검증해야 한다.
4. 레일 재료와 단차·침하·뒤틀림 재현 방법을 확정해야 한다.
5. 실제 주행 데이터를 수집하고 라벨링해야 한다.
6. 합성 데이터 모델을 실측 데이터로 재학습·평가해야 한다.
7. 백엔드와 Godot의 WSS 실연동을 다시 검증해야 한다.
8. 좌·우 레일 데이터 계약과 현재 장치 식별자를 확정해야 한다.
9. 조립 완료 모형의 반복 시운전 절차를 작성하고 시험해야 한다.
10. 최종 보고서의 진행률과 성능 수치는 증빙 자료와 함께 갱신해야 한다.
