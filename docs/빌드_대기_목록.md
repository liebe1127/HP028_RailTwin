# 빌드·배포 대기 목록

코드는 고쳤지만 아직 빌드·설정·확인이 남은 작업을 모은다. 다음에 한꺼번에 빌드할 때 이 목록을 위에서부터 처리하고, 끝난 항목은 지운다.

---

## 1. 레일 좌표 통일 + 180 cm (브랜치 `claude/rail-coordinate-180cm`)

### 무엇을 고쳤나

- 서버는 레일 길이를 100 cm로 알고 있었고(실물·Unity 모델은 180 cm), 결함 위치 기준점도 두 가지가 섞여 있었다
  - 주행 파형 적합(`pass_analysis.py`)은 레일 왼쪽 끝 기준(예: 600~1200 mm)
  - 구간 규칙(`rail_defect.py`)과 Unity·대시보드 색칠은 엔코더 기준 + 구동바퀴 58 cm
  - 그래서 실측 주행 중에는 결함 색이 실제보다 약 58 cm 뒤(118~158 cm)에 칠해졌다. 실측 CSV 재생 화면은 58 cm를 더하지 않아 맞아 보였다
- 이제 서버의 모든 결함 위치는 **레일 좌표(레일 왼쪽 끝 = 0 mm)**다
  - `rail_defect.py`: 레일 좌표 = 좌 엔코더 + `SENSOR_START_MM`(기본 290). 더미 샘플은 이미 레일 좌표라 더하지 않는다. 파형 적합에는 엔코더 원시값을 그대로 넘긴다
  - `main.py`, `.env.example`, `docker-compose*.yml`: 기본값 `RAIL_LENGTH_CM=180`, `RAIL_SEGMENT_COUNT=36`(구간 50 mm)
  - `frontend/index.html`, `RailTwinController.cs`: 결함 색칠과 결함 목록에서 58 cm 보정을 뺐다. 58 cm는 대차 위치 표시에만 쓴다
- 검증(이 브랜치, 9/28 실측 24회 재생): 판별 18/18 그대로. 세 결함 모두 Unity 색칠 위치가 실제 결함 위치 60~120 cm와 같다

### 빌드할 것

- [ ] **Unity WebGL 다시 빌드** (`RailTwinController.cs`의 `Paint()`가 바뀜). 맥에서:
  ```bash
  UNITY="/Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity"
  "$UNITY" -batchmode -nographics -quit \
    -projectPath "$(pwd)/unity/RailTwinRails" \
    -executeMethod RailTwinWebGLBuild.Build \
    -logFile unity-webgl-build.log
  bash scripts/sync_unity_webgl.sh   # Build/ → frontend/unity/Build/
  ```
  `frontend/unity/Build/`의 바뀐 파일 4개를 **이 브랜치에 같이 커밋**한다

### 서버 설정 (GitHub로 바뀌지 않음, NCP 서버에서 직접)

- [ ] 서버 `.env`를 아래처럼 고친다. 2026-10 서버 백업의 `.env`에는 `RAIL_LENGTH_CM=100`, `RAIL_SEGMENT_COUNT=20`이 적혀 있어서, 코드 기본값을 바꿔도 그대로 덮어쓴다
  ```
  RAIL_LENGTH_CM=180
  RAIL_SEGMENT_COUNT=36
  SENSOR_START_MM=290
  ```
- [ ] 고친 뒤 FastAPI를 재시작한다. 정상 기준선(`rail_baseline.json`)은 다시 등록하지 않아도 된다. 기준선은 이음부로 맞춘 격자라 이번 좌표 변경과 무관하다

### 배포 순서 (중요)

- [ ] **Unity 빌드 파일이 이 브랜치에 들어간 뒤에만 `main`에 합친다.** 서버·대시보드만 먼저 배포되면, 예전 Unity 빌드가 새 레일 좌표에 58 cm를 또 더해서 Unity 화면만 어긋난다
- [ ] 합치기 전에 맥에서 전체 테스트를 돌린다. 이 브랜치는 클라우드에서 fastapi가 없어 `tests/test_sensor_contract.py`와 실측 재생만 돌렸다
  ```bash
  python3 -m venv .venv && source .venv/bin/activate
  pip install -r requirements.txt pytest
  pytest -q
  python replay_csv.py "배준호_전달/레일측정데이터"   # 판별 18/18 확인
  ```
- [ ] 배포 뒤 대시보드에서 확인: 실측 주행 1회 후 결함 목록 구간이 60~120 cm 근처인지, Unity와 아래 rail_risk 막대가 같은 곳을 칠하는지

### 확인 필요 (하드웨어 문서 받은 뒤)

- [ ] `SENSOR_START_MM`(엔코더 0일 때 센서의 레일 좌표) 실측값. 지금 290 mm는 9/28 실측 24회에서 이음부 위치로 역산한 중앙값이다(범위 254~316 mm). 예전 코드 값은 250 mm였다
- [ ] 구동바퀴 출발점 58 cm(`WHEEL_START_CM`, Unity `WheelStartCm`)와 센서 위치 290 mm가 대차 치수와 맞는지. 역산값대로면 센서는 구동바퀴보다 약 29 cm 뒤에 있다
- [ ] 엔코더 배율. 9/28 실측에서 이음부 간격(600 mm)으로 본 배율이 0.84~0.99(중앙값 약 0.89)였다. 엔코더가 실제보다 약 10% 더 센다. 파형 적합은 이음부로 자동 보정하지만, 주행 중 구간 규칙은 보정하지 않아 레일 끝 쪽으로 갈수록 위치가 밀린다(예: 120 cm 이음부가 125 cm 근처로)
