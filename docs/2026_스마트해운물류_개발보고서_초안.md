# 본문

## PDF 4쪽 — I. 작품 개요

### 1. 작품 소개

#### 기획 의도

- 갠트리 크레인의 운행 과정에서 생성되는 동적 센서 데이터를 활용해 하부 주행 레일의 이상 징후를 조기에 파악한다.
- 센서 계측, 특징 공학, AI 추론, 시계열 저장 및 실시간 시각화를 하나의 파이프라인으로 연결한다.
- 위험도와 거리 좌표를 함께 제공하여 유지보수 담당자가 우선 점검할 좌·우 레일 구간을 특정하도록 돕는다.

#### 작품 내용 및 정의

- RailTwin은 관성·거리 계측 모듈, FastAPI 실시간 서버, PyTorch RBF 대리 모델, InfluxDB, 웹 대시보드와 Godot 3D 화면으로 구성된 레일 상태 모니터링 프로토타입이다.
- 핵심 예측 대상은 하부 주행 레일의 단차·국부 침하·뒤틀림 등 기하 이상이다.
- 원시 센서값은 롤링 윈도우, 웨이블릿 디노이징, 파고율 등 특징 공학을 거쳐 모델에 입력한다.
- 현재 소프트웨어 파이프라인과 합성 데이터 시연 기능은 구현되어 있다. 사용자 확인 기준으로 센서 모듈 배선, ESP32-C3 펌웨어 동작, 구동부 출력과 전체 모형 조립을 완료했으며 전기적 측정·교정, 반복 주행, 실측 저장과 모델 검증이 남아 있다.

### 2. 작품의 개발 배경 및 필요성

#### 작품 제작 동기

- 대형 갠트리 크레인의 하부 주행 레일은 반복 주행 하중과 주변 환경의 영향을 지속적으로 받는다.
- 국부적인 단차·침하·뒤틀림은 충격과 진동을 증가시키고 장기적으로 설비 안정성과 유지보수 부담에 영향을 줄 수 있다.
- 정기 점검과 육안 확인만으로는 점검 주기 사이에 발생하거나 운행 중에만 나타나는 동적 이상을 놓칠 수 있다.

#### 제작 목적

- 운행 중 가속도·자이로·거리 변화를 지속적으로 수집해 레일 이상 징후를 분석한다.
- 특징 공학과 비선형 모델을 이용해 정상 진동과 순간 충격을 구분할 수 있는 위험 지표를 만든다.
- 위험 위치를 디지털 트윈에 매핑하여 현장 점검과 상태 기반 유지보수의 의사결정을 지원한다.

### 3. 작품의 특징 및 장점 / 국내·외 기술 현황 및 본 프로젝트의 차별성

#### 1) 국내·외 기술 현황

- 산업 설비 분야에서는 진동 센서와 시계열 분석을 이용한 상태 감시·예지보전 기술이 활용되고 있다.
- 디지털 트윈은 실물 설비의 센서 데이터를 가상 모델과 연결하여 상태와 위치를 직관적으로 표현하는 방향으로 발전하고 있다.
- 본 작품은 범용 센서, 특징 공학, 경량 대리 모델과 위치 기반 3D 시각화를 결합하여 갠트리 크레인 하부 주행 레일을 교육·시연 규모에서 종단 간 구현하는 데 초점을 둔다.
- 관련 논문·특허·상용 제품과의 정량 비교 및 출처: `[확인 필요: 팀 선행기술 조사 결과]`

#### 2) 작품의 특징 및 장점(차별성)

- **운행 중 가변 계측:** 별도 정지 점검뿐 아니라 주행 중 동적 가속도·자이로·거리 변화를 함께 다룬다.
- **특징 공학 기반 분석:** 웨이블릿 디노이징으로 노이즈를 완화하고 파고율로 단차 충격의 피크 특성을 강조한다.
- **위치 기반 위험도:** 거리값을 레일 구간에 대응시켜 좌·우 레일의 누적 위험도를 색상으로 표시한다.
- **장애 격리형 파이프라인:** 센서 미연결, DB 저장 실패, WebSocket 종료가 전체 시연을 즉시 중단시키지 않도록 구성한 소프트웨어 프로토타입이다.
- **무선 센서 연결:** ESP32-C3가 WiFi WebSocket으로 센서 배치를 직접 전송하며, 장치·레일 식별자와 순번을 이용해 다중 센서 모듈로 확장할 수 있다.
- **검증 범위의 명시:** 합성 데이터 시연과 실제 계측 성능을 구분하고, 실측 데이터 확보 후 정량 평가하도록 설계하였다.

## PDF 5~8쪽 — II. 작품 내용

### 1. 목표 시스템 구성도

#### 1) 예상결과물

**HW 결과물**

- ESP32-C3 Mini, MPU-6050, ADS1115, GTRIC LR18-08U M18 아날로그 유도형 근접 센서로 구성한 센서 모듈
- 구동 모터·바퀴·배선·센서 모듈을 3D 출력 외피 내부에 수납한 하부 구동부
- 약 1.4m급으로 계획된 분해·재조립형 축소 크레인·레일 모형 `[최종 치수·재료 확인 필요]`
- 단차·국부 침하·뒤틀림 조건을 반복 재현할 수 있는 시험 구간 `[구현 방식 확인 필요]`

**SW 결과물**

- FastAPI 기반 비동기 센서 수집·처리 서버
- 웨이블릿 디노이징·파고율 특징 추출 모듈
- PyTorch RBF 레일 변형 위험 추론 모델
- InfluxDB 시계열 저장 및 WebSocket 실시간 전송 기능
- 실시간 웹 대시보드
- Godot 기반 크레인 위치·좌우 레일 위험도 시각화
- 센서 미연결 환경의 파이프라인 점검용 더미 스트리머

#### 2) SW/HW구성도(또는 서비스흐름도)

1. **계측:** MPU-6050이 3축 가속도·3축 자이로를 계측하고, GTRIC LR18-08U 센서가 금속 레일과의 1–8mm 간격 변화를 0–10V 아날로그값으로 출력한다.
2. **변환·엣지 처리:** ADS1115가 입력 회로를 거친 아날로그값을 디지털로 변환하고, ESP32-C3 Mini가 정지 노이즈를 억제한 데이터를 전송한다.
3. **실시간 처리:** FastAPI Producer가 데이터를 비동기 Queue에 적재하고 Consumer가 특징 추출·추론·저장·전송을 수행한다.
4. **특징 공학·AI:** 가속도 롤링 윈도우에 웨이블릿 디노이징을 적용하고 파고율 등 특징을 정규화하여 RBF 모델에 입력한다.
5. **저장·전송:** 센서 특징과 `PRED_RAIL_DEFORM`, 구간별 `rail_risk`를 InfluxDB와 WebSocket 경로로 처리한다.
6. **시각화:** 웹은 데이터·모델·서버 상태를 표시하고, Godot는 `distance_x`와 좌·우 `rail_risk`를 이용해 위치 및 색상을 갱신한다.

> 삽입 권장: 현재 센서 구성을 반영해 새로 제작한 HW/SW 2층 구성도. 기존 `docs/system-architecture.png`는 과거 센서가 표시되어 있으므로 사용하지 않는다.

### 2. 주요 적용 기술

#### 1) 현재 센서 모듈과 엣지 계측

- ESP32-C3 Mini와 MPU-6050은 가속도·자이로 계측 및 엣지 제어를 담당한다.
- 실제 보유 GTRIC LR18-08U M18 센서의 몸체 라벨에서 DC 15–30V 동작 전압, 0–10V 출력 전압, 1–8mm 감지 거리를 확인했다.
- 라벨 배선도는 갈색 전원(+), 청색 전원(-), 흑색 아날로그 출력을 나타낸다. 0–10V 출력은 ADS1115에 직접 연결하지 않고 입력 허용 범위에 맞춘 분압·보호 회로를 거쳐야 한다.
- 현재 ESP32-C3 펌웨어 동작은 사용자가 확인했다. 핀 배치·샘플링 주기·전송 형식의 저장소 반영, 교정과 반복 계측은 `[진행 중]`이다.
- 취소된 초기 프로토타입의 펌웨어는 개발 이력으로만 보존하며 현재 장치의 성과로 사용하지 않는다.

#### 2) 비동기 실시간 데이터 처리

- FastAPI의 센서 전용 WebSocket에서 JSON 배치를 검증·ACK하고 비동기 Queue–Consumer 구조로 저장·추론·방송을 수행한다.
- 제한된 Queue가 포화되면 오래된 데이터를 제거해 최신 상태 처리를 우선한다.
- 필드 단위 파싱 오류, InfluxDB 저장 실패 및 종료된 WebSocket 연결을 분리 처리하는 로직이 구현되어 있다.
- 현재 백엔드의 일부 센서 키와 기본 장치 식별자는 취소된 초기 데이터 계약에 의존하므로 ESP32-C3 기준 계약으로 이관해야 한다.

#### 3) 웨이블릿 디노이징과 파고율

- 롤링 윈도우의 동적 가속도 신호를 `sym3` 웨이블릿으로 분해하고 상세 계수에 soft-thresholding을 적용한다.
- 파고율은 `신호 절댓값의 최댓값 ÷ RMS`로 계산하여 지속 진동보다 순간 충격 피크에 민감한 특징을 만든다.
- 원시 센서값만으로 판정하지 않고 디노이징 결과와 충격 특징을 모델 입력에 포함한다.

#### 4) PyTorch RBF 대리 모델

- 학습 가능한 가우시안 RBF 중심과 선형 출력층을 이용해 정규화된 특징에서 레일 변형 위험 지표를 출력한다.
- 저장소에는 합성 데이터 1,500개, 32샘플 윈도우, 64개 RBF 중심, 200 epoch로 구성된 파이프라인 검증용 학습 스크립트가 있다.
- 위 설정과 학습 결과는 SILS 및 인터페이스 확인용이며 실제 단차·침하·뒤틀림 판별 정확도를 입증하지 않는다.
- 현재 학습 입력에는 취소된 초기 센서 필드가 남아 있어 MPU-6050·GTRIC 기반 최종 특징 구조로 재정의하고 실측 데이터로 재학습해야 한다.

#### 5) 위치 기반 위험도와 디지털 트윈

- 서버는 거리값을 레일 구간 인덱스로 변환하고 파고율과 예측값을 위험도로 정규화하여 구간별 최댓값을 누적한다.
- WebSocket 페이로드는 좌·우 레일 데이터, `PRED_RAIL_DEFORM`, `rail_risk`, 레일 길이와 구간 수를 전달한다.
- Godot 스크립트는 크레인 위치를 보간 이동시키고 각 레일 구간을 파랑–초록–노랑–빨강 계열로 갱신하도록 구현되어 있다.
- 최종 Godot 씬·상용 3D 자산 결합과 실제 WSS 운영 연결은 `[검증 필요]`이다.

#### 6) 더미 스트리머

- 센서 미연결 시 약 1m 레일을 왕복하며 40~50cm 구간에 단차 충격을 모사하는 합성 신호를 생성한다.
- 더미 스트리머는 백엔드·AI·WebSocket·화면의 데이터 흐름을 반복 점검하기 위한 기능이다.
- 더미 신호의 위험값, 파고율 또는 모델 출력은 실제 계측 정확도·재현율·오탐률 근거로 사용하지 않는다.
