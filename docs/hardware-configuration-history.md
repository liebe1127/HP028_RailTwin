# 센서 하드웨어 구성 변경 이력

## 현재 기준 구성

현재 센서 모듈의 설계·구현·문서 작성은 다음 구성을 기준으로 한다. 좌·우 레일 구동부에 각각 독립 센서 노드가 있다.

- 왼쪽 노드: ESP32-C3 Mini (`rail-left-01`, `rail_side=left`)
- 오른쪽 노드: ESP32-C3 Mini (`rail-right-01`, `rail_side=right`)
- 각 노드 관성 센서: MPU-6050
- 각 노드 외부 ADC: ADS1115
- 각 노드 거리 계측: GTRIC LR18-08U M18 아날로그 유도형 근접 센서
- 전원: 18650 배터리, 승압 모듈 및 센서 사양에 맞는 별도 전원 구성

2026-08-23 실제 보유 센서 몸체 라벨 사진으로 다음 사양을 확인했다.

- 모델: LR18-08U
- 동작 전압: DC 15–30V
- 출력 전압: 0–10V
- 감지 거리: 1–8mm
- 배선 라벨: 갈색 전원(+), 청색 전원(-), 흑색 아날로그 출력

따라서 GTRIC 센서 출력은 ADS1115에 직접 연결하지 않고, ADS1115 입력 허용 범위에 맞춘 분압·입력 보호 회로를 사용해야 한다. 분압비, 보호소자, 공통 접지와 실제 전원 출력은 회로 제작 전에 확정하고 멀티미터로 검증한다.

2026-08-23 사용자 제공 실물 사진에서 ESP32-C3 Mini, MPU-6050, ADS1115, 전원부, 18650 배터리, GTRIC LR18-08U와 배선된 센서 모듈 구성을 확인했다. 사용자 확인에 따르면 ADS1115용 분압·보호 회로도 이 구성에 포함되어 있다. 다만 사진만으로 저항값·보호소자 정격, 실제 분압비, 출력전압 및 펌웨어 수신 성공 여부까지 확인할 수는 없으므로 전기적 측정과 동작 시험 기록은 별도로 남긴다.

2026-08-23 사용자 최신 확인 사항:

- 현재 센서 부품 수령 완료
- 센서 모듈 배선 완료
- ESP32-C3 펌웨어 동작 확인
- 구동부 출력 완료
- 전체 모형 조립 완료
- 반복 주행 시험 미실시
- 실측 데이터 저장 미실시

위 완료 상태는 사용자 확인을 기준으로 기록한다. 펌웨어 원본·실행 로그·전압 측정값·조립 사진이 저장소에 모두 포함되어 있다는 뜻은 아니며, 반복 주행과 실측 데이터 증빙은 후속 작업이다.

## 현재 펌웨어 저장소 반영 상태

2026-08-23 저장소에 `firmware/esp32_c3_rail_sensor/` 경로로 현재 센서용 펌웨어를 추가했다.

- ESP32-C3 → WiFi → MQTTS QoS 1 → NCP Mosquitto → FastAPI 구독
- MPU-6050 100Hz, ADS1115 20Hz 수집
- 엔코더 위치, LR18 거리, ADC 원시값·전압, 가속도·자이로 전송
- 좌·우 고유 장치 프로필, 재부팅 식별자, QoS 1, LWT, 순번과 유실 배치 계수 포함

이는 소프트웨어 구현 완료를 뜻하며 두 실물 보드의 컴파일·업로드와 핀맵, 엔코더 회전당 계수·방향·영점, LR18 전압-거리 변환, 분압·보호 회로의 실측 검증 완료를 뜻하지 않는다. 각 노드의 `NODE_ENABLE_LINEAR_DISTANCE_ESTIMATE`는 교정 전까지 비활성 상태로 둔다.

## 취소된 초기 프로토타입

다음 구성은 초기 데이터 수집 검증에 사용했으나 취소되었으며, 현재 하드웨어로 사용하지 않는다.

- MCU: ESP32-S3-WROOM-1
- 가속도 센서: ADXL345
- 거리 센서: HC-SR04
- 관련 파일: `firmware/crane_sensor/crane_sensor.ino`

해당 펌웨어와 문서는 개발 과정 및 과거 실험을 열람하기 위한 이력 자료로 보존한다. 신규 설계, 배선, 펌웨어, 보고서 및 부품 구매의 기준으로 재사용하지 않는다.

## 적용 원칙

1. 현재 하드웨어를 설명할 때는 ESP32-C3 Mini, MPU-6050, ADS1115, GTRIC LR18-08U M18(0–10V) 구성을 사용한다.
2. ESP32-S3, ADXL345, HC-SR04를 언급할 때는 반드시 `취소된 초기 프로토타입`이라고 표시한다.
3. 기존 백엔드와 AI 코드가 과거 센서 필드에 의존하면 현재 센서 데이터 계약에 맞게 별도로 이관한다.
4. 과거 자료는 삭제하지 않고 이력으로 보존하되 현재 구성과 혼합하지 않는다.
