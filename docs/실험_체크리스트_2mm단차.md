# 주행 실험 체크리스트 — 정상 레일 · 2 mm 이음부 단차

목적: 새 서버 코드(레일 좌표 통일, 180 cm)와 펌웨어에서 결함 탐지가 실측으로 맞게 작동하는지 확인한다. 실시간 판정은 **v2(AI 끔)** 로 보고, v1 · v2+AI 는 실험 뒤 같은 CSV 를 재생해 비교한다.

레일: 아연 각파이프(25×25 mm, 60 cm) 3개를 3D 프린팅 이음부로 이은 180 cm. 정상용 이음부와 단차용 이음부를 바꿔 끼운다.
단차: **두 번째 이음부(120 cm)에서 다음 파이프가 2 mm 낮아지는** 모양. 9/28(가운데 파이프 전체가 2 mm 높음, 60·120 cm 두 곳)과 모양이 다르다.
정답: 이음부 단차 · 위험 (2 mm > 한계선 1.0 mm). 위치 120 cm 근처(재생 결과 구간 110~130 cm).

## 판정 방식 결정 (PM)

오늘 모양을 배용진 가상 모형으로 만들어 미리 재생했다(정상 9회 · 단차 6회, 레일 굴곡 0.10/0.15/0.25 mm 세 가지). 가상 데이터라 충격(가속도)은 없고 주행 후 판정만 본 결과다.

| | v1 | v2 | v2 + AI |
|---|---|---|---|
| 정상 6회 | 6/6 정상 | 6/6 정상 | 6/6 정상 |
| 단차 6회 | **2~4/6**, 크기 약 1.0 mm, 마지막 판정이 "정상"인 경우 있음 | 6/6 위험, 2.0 mm, 110~130 cm | 6/6 위험, AI 2.1~2.4 mm |

v1 은 9/28 모양(가운데 파이프 전체 단차)에만 맞춘 판정기라 이음부 한 곳 단차의 크기를 절반으로 본다. 주행이 끝나면 이 결과가 구간 규칙보다 우선하므로, v1 그대로면 실시간 화면에서 단차가 사라질 수 있다.

**결정 (PM, 11/7): 오늘 서버 판정은 v2, AI 는 끔(재적응 전).** 실험 뒤 재생 보고서에 v1 · v2 · v2+AI 가 모두 나온다.

v2 를 켜면 "주행 분석 결과로 감속·정지(앞 2구간 미리 보기)"도 켜진다. 그대로 두면 단차 3회째부터 대차가 120 cm 이음부 앞에서 멈춰 그 주행은 분석에 못 쓴다. 그래서 **데이터를 모으는 동안 끄고, 마지막에 켜서 정지만 확인**한다. 서버를 끄지 않고 바꾸므로 3회 평균 기록이 유지된다.

```bash
# 끄기 (데이터 수집)                                  # 켜기 (정지 확인)
curl -k -X POST https://223.130.128.198:8000/api/motion_from_pass \
     -H 'Content-Type: application/json' -d '{"enabled": false}'    # true 로 바꾸면 켜짐
```

9/28 단차 데이터로 확인: 끄면 4회째도 끝까지 평속, 켜면 결함 구간(500 mm~) 앞 403 mm 에서 정지 명령.

## 1. 공통 주행 절차 (매 회)

1. 대차를 출발 자세에 놓는다 (구동바퀴가 레일 왼쪽 끝에서 58 cm)
2. 보드 **리셋(EN)** → 전원 번호가 바뀌어야 CSV 가 주행 하나당 한 파일로 나뉜다
3. 대시보드에서 **위치 리셋**
4. **BOOT** 한 번 → 전진 25초 후 정지
5. 충격 정지·멈춤·탈선이 있었으면 그 회차 번호를 적고 다시 달린다

## 2. 정상 레일 9회

정상용 이음부를 끼운 상태 (두 이음부 모두 평평).

- [ ] 대시보드 **기준선 모드 켜기**
- [ ] 정상 1~3회 (기준선)
- [ ] 기준선 모드 **끄기** → 기준선 횟수 3 확인
- [ ] 정상 4~9회 (오경보 확인 6회): 결함 목록이 비어 있어야 한다

오경보 확인을 6회로 두는 이유: 9/28 정상 6회 중 2회(31차 센서 어긋남, 35차)는 v2(AI 끔) 재생에서 결함으로 잡혔다. 기준선을 5회로 늘려도 같았다. 오늘 정상 주행에서 이런 회차가 얼마나 나오는지 보는 것이 v2를 켤지 판단하는 근거가 된다. 정상 9회는 AI 재적응(5회 이상 필요)에도 그대로 쓴다.
