# AI 크기 추정 경로 (rail_ai.py) — 판정 엔진 v2 에 붙이는 법

작성 2026-11-04, 배용진. 기본은 꺼져 있다. 켜지 않으면 동작이 전과 같다.

## 무엇인가

- `rail_ai.py` — 좌·우 변화 신호(기준선을 뺀 센서 거리)에서 **단차 크기·처짐 크기(mm)** 를 내는 1D CNN 5개의 평균. numpy 만 쓴다 (torch 불필요, 1회 추정 20 ms 안팎).
- `rail_ai_weights.npz` — 가중치 1.4 MB. 가상 결함 주행 2,520회 + 실측 정상 주행 4회 배경으로 학습. **실측 결함 주행은 학습에 쓰지 않았다.**
- 센서 어긋남 검사 `rail_ai.sensor_check` — 한쪽 센서 신호가 이음부(600/1200)를 지나는데 부호가 안 바뀌고 0.7 mm 이상 유지되면 `sensor_check`. 강체 파이프 레일에서는 나올 수 없는 모양이라 레일 결함이 아니라 센서 문제로 본다 (9/28 31차가 이 경우).

## 켜는 법

```
RAIL_JUDGE=v2 RAIL_AI=1 uvicorn main:app ...
```

`RAIL_JUDGE=v2` 가 먼저 켜져 있어야 한다 (rail_defect.py 가 rail_judge_v2.PassAnalyzerV2 를 쓰는 경로). `RAIL_AI=1` 이면 PassAnalyzerV2 가 시작할 때 가중치를 읽고, 주행마다:

1. 위치 보정·격자화·레일 끝 높이 복원은 전과 같다 (위치, 쪽, 좌우 높이차는 여기서 나온다)
2. 원시 표본을 300~1500 mm, 2 mm 격자에 얹고 기준선을 뺀 뒤 AI 로 단차·처짐 크기를 잰다 → `sizes_mm["joint_step"]`, `sizes_mm["vertical"]` 만 AI 값으로 바뀐다
3. 좌우 높이차 판별(차이가 평균보다 크면 처짐 0), 3회 평균, 단계 규칙(0.5 주의 / 1.0 위험)은 그대로
4. 센서 어긋남이 잡히면 `defect_type="sensor_check"`, `stage="ok"`, `low_confidence=True` 로 내고 그 주행은 3회 평균에 넣지 않는다

결과 dict 에 `ai_sizes_mm`, `ai_spread_mm`(모델 5개 사이 표준편차, 클수록 불확실), `sensor_check`(목록) 가 추가된다.

## 같이 바뀐 것 (RAIL_AI 와 상관없이 v2 에 적용)

- 기준선 등록이 **평균 → 중앙값**(3회 이상일 때). 정상 주행 중 한 회차에 센서 어긋남이 있어도 기준선에 섞이지 않는다.
- v2 도 v1 처럼 `RAIL_BASELINE_FILE` 에 기준선을 저장하고 시작할 때 읽는다 (main.py 의 재생 API 가 `pass_analyzer.store` 를 쓰므로 필요).
- 센서 어긋남 검사는 신호가 평평하고 이음부 ±250 mm 밖까지 이어질 때만 표시한다 (큰 받침 침하의 봉우리와 구분).
- AI 가 켜져 있을 때 좌우 높이차 구분: 복원 높이의 좌우 차이가 평균보다 커도 AI 가 양쪽 침하를 그 차이의 절반 이상으로 읽으면 AI 값을 믿는다 (다시 놓임으로 복원 차이가 커진 가상 주행에서 처짐을 놓치던 것을 고침).

## 가상 주행 재생 (대시보드·Unity 에서 가상 시운전 보기)

`POST /api/replay_virtual` — `가상주행/` 폴더의 가상 모형 주행 CSV 를 엔진에 넣고 결과를 대시보드와 Unity 레일에 보낸다. 실측 재생 API 와 같은 길이다.

- `가상주행/manifest.csv`: group(baseline / HF / C / HF+C), placement_id, rep, 정답 크기와 단계. 기준선용 정상 6회 + 시나리오별 위험 배치 2개와 주의 배치 1개, 각 3회
- 요청: `{"group": "HF+C"}` 또는 `{"group": "C", "placement_id": 21}`. `"all"` 이면 세 시나리오를 차례로
- 같은 배치 3회를 이어서 넣으므로 3회째 결과가 판정 단계가 된다. 응답의 `played` 에 회차별 결과와 정답이 같이 온다
- 화면 제목이 "가상 주행 재생 → 주행 분석 → Unity 레일" 로 바뀐다

PowerShell 예:

```
Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/replay_virtual -ContentType "application/json" -Body '{"group":"C","placement_id":21}'
```

RAIL_JUDGE=v2 RAIL_AI=1 로 켠 서버에서 위 배치들의 3회째 판정: HF 5 → 단차 위험 3.4 (정답 3.0), HF 10 → 단차 위험 1.45 (정답 1.35), C 11 → 처짐 위험 2.9 (정답 2.2), C 21 → 처짐 위험 4.5 (정답 3.8), HF+C 27 → 처짐 위험 4.1 (정답 단차 2.8 처짐 2.7). 주의 배치는 위험으로 올려 보거나 놓치는 경우가 있다 (가상에서 크기를 크게 재는 성질).

## 실측 24회 재생 결과 (replay, 기준선 정상 6회 → 각 6회)

| 배치 | 규칙(v2) | AI 켬 |
|---|---|---|
| 정상 | 31차 cross_level 3.2 로 표시(1회째라 단계는 정상), 나머지 정상 | 31차 `sensor_check`, 나머지 정상 |
| 단차 2 mm | joint_step 1.9~2.0, 3회째부터 위험 | joint_step 2.0, 3회째부터 위험 |
| 처짐 2 mm | vertical 2.2~2.4, 위험 | vertical 1.2~2.3 (3회 평균 1.4~1.6), 위험 |
| 좌우 높이차 2 mm | joint_step 0.7 주의 (우측 0.7 단차) | cross_level 2.7~3.0 주의 |

처짐 크기는 AI 가 규칙보다 작게 잰다. 500 mm 현측정이 긴 변형을 작게 보는 성질 때문에 2 mm 처짐 신호가 0.4 mm 밖에 안 되어, 다시 놓임 변형(0.3 mm)과 겹치면 흔들린다. 3회 평균으로 보완한다.

## 학습·검증 기록

프로젝트 문서 `claude/AI단계_모델비교.md` (학습 코드 `ai_train.py`, `ai_train_v2.py`). 가상 검증(배치 분리) 종류 79 % / 단계 81 %, 실측 18회 종류 17/18 · 단계 17/18 (센서 검사 뒤 18/18).

## 하지 않은 것

- 좌우 높이차 크기는 AI 가 재지 않는다 (4~6 mm 실험 뒤 추가 예정). 규칙 값 그대로.
- Unity·대시보드는 `sensor_check` 종류를 아직 모른다. 표시 문구만 추가하면 된다.
