# 트윈·대시보드 좌표계 확인과 수정 (2026-11-03)

## 확인 (레포 9/29 커밋)
1. 서버 main.py `build_side_ws_payload`: `distance_x = position_mm / 10` — 좌 엔코더 원시값(cm). 미끄러짐 보정 없음.
2. 서버 rail_defect `_risk_array`: 주행 분석 결과가 있으면 from_mm/to_mm(센서 기준 레일 좌표)로 구간 6~13을 칠하고, 없을 때는 옛 구간 규칙이 엔코더 원시 위치로 칠함 → 같은 배열의 좌표계가 상황에 따라 바뀜.
3. 대시보드 frontend/index.html: `WHEEL_START_CM = 58`. 실시간이면 대차 위치 = 58 + 엔코더 cm, 위험 구간도 원점 58 cm. 실측 재생이면 둘 다 그대로.
4. Unity RailTwinController.cs: `WheelStartCm = 58`. 실시간(wheel=1)이면 구간 위치에서 58을 빼고 칠함.

결론: 실시간에서는 결함 구간(레일 54~126 cm)이 화면에 112~180 cm로 칠해지고 대차 위치는 미끄러짐만큼 어긋남. 실측 재생에서는 구간은 맞지만 대차가 센서보다 25~30 cm 뒤에 그려짐. 원인은 한 필드에 두 좌표계가 섞인 것.

## 수정함 (사용자 PC의 레포 작업 트리, 커밋 전)
- pass_analysis.py: 주행 결과에 `joint_raw_mm` 추가 (+1줄)
- rail_defect.py: `rail_x_mm()` 변환, 구간 번호를 레일 좌표로, 감속·정지를 주행 분석 결과에서 앞 2구간 미리 보기, `RAIL_JUDGE=v2` 옵션 (+50줄)
- main.py: 페이로드에 `rail_x_mm`, `coords: "rail_sensor"` (+8줄)
- frontend/index.html: `rail_x_mm` 있으면 58 cm 보정 없이 사용, Unity 에 `wheel: 0` (+19/−10줄)
- 새 파일: rail_judge_v2.py (수정안 판정기, 옵션), docs/coords-rail-sensor.md (변경 설명)
- Unity: 변경 없음 (wheel=0 경로가 x 를 대차 중심으로 처리)

## 확인 결과
- 실측 24회 재생: 정상 6회를 기준선으로 등록한 뒤 결함 18회 판별 18/18 유지 (v1, 논문 3.3 과 같은 방식). `RAIL_JUDGE=v2`도 동작 (좌우 높이차 구성은 우 레일 0.7 단차를 주 결함으로 보고 → replay_csv 집계상 12/18)
- 가상 주행(판정 뒤 4회째, 80배치): 서버가 위험으로 판정한 23배치 전부 정지 신호, 첫 신호 결함 앞 중앙값 −239 mm, 결함 앞에서 나온 비율 100 % (수정 전: 정지 0, 결함 뒤 +191 mm)
- 대시보드 JS: 문법 검사만 함(node --check). 실제 화면은 서버를 띄워 확인 필요
