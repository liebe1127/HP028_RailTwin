# AI 단계 — 가상으로만 학습한 모델을 실측 18회로 비교하고, 서버 판정 엔진에 붙임

작성 2026-11-04. 앞 단계(3단계 수정 후 재검증, 과적합 검사)에 이어서. 1차·2차 두 번 돌렸다.

## 원칙

- 실측 결함 주행(단차 6·처짐 6)은 어떤 학습·튜닝·모델 고르기에도 쓰지 않는다.
- 1차: 실측은 평가에만. 2차: **학습에 가상 결함 + 실측 정상 일부**를 허용했다. 현장에서 정상 주행은 설치 때 늘 얻을 수 있고 결함 주행은 못 얻기 때문이다. 실측 정상을 학습에 쓸 때는 1회씩 빼 가며 5번 학습해(교차검증) 뺀 회차로 평가했다.
- 좌우 높이차는 4~6 mm 실험 뒤에 넣기로 해 이번에도 뺐다.
- 실측 18회는 정상 6, 단차 6, 처짐 6 이다. 논문 3.3 절의 서버 재생 18회는 정상 6회를 기준선으로 쓰고 단차·처짐·좌우 높이차 각 6회를 재생한 것이라 다른 묶음이고, 논문 3.2 절의 회차별 판별은 24회 중 23회다. 이 문서의 18/18 은 모두 AI 평가 묶음 18회 기준이다.
- 크기 → 판정은 모든 방법이 같은 규칙을 쓴다. 0.5 mm 이상 결함 있음, 1.0 mm 이상 위험, 3회 평균.

## 1차 — 세 가지 방법

| 방법 | 어떻게 배우나 |
|---|---|
| A 규칙 | 학습 없음. 이음부 주변 신호에서 크기를 바로 읽음. 지금까지의 기준선 |
| B 혼합형 | 규칙 추정값 + 물리 특징을 넣고 GBR 이 규칙의 오차만 배움 |
| C1 1D CNN | 좌·우 변화 신호 601점×2 를 바로 넣음. 학습 중 다시 놓임·실측 잡음·위치 ±6 mm·배율 ±5 % 를 무작위로 섞음. 씨앗 3개 평균 |

학습 가상 2,016회, 가상 검증 504회(배치 단위 분리), 실측 18회.

| 방법 | 가상 검증: 종류 / 단계 / 단차 오차 / 처짐 오차 | 실측 종류 | 실측 단계 | 단차 크기 (정답 2) | 처짐 크기 (정답 2) |
|---|---|---|---|---|---|
| A 규칙 | 62 % / 69 % / 0.47 / 0.74 | 12/18 | 17/18 | 1.87 ± 0.02 | 1.37 ± 0.10 |
| B 혼합형 | 78 % / 80 % / 0.21 / 0.39 | 15/18 | 12/18 | 1.94 ± 0.19 | 0.80 ± 0.43 |
| C1 CNN | 81 % / 82 % / 0.17 / 0.31 | 17/18 | 15/18 | 1.39 ± 0.11 | 1.24 ± 0.40 |

읽는 법. 가상 안에서는 CNN 이 규칙보다 분명히 낫다. 실측에서 종류는 CNN 이 낫다(규칙은 단차 회차 5/6 을 "단차+처짐"으로 읽음). 단계는 규칙이 앞섰고, 차이는 CNN 이 처짐 3회를 "주의"로 본 것. 단차 크기도 CNN 이 1.39 로 작게 봤다.

### 1차에서 찾은 두 가지 원인

**단차를 작게 본 원인.** 실측 단차 주행의 850~950 mm(두 바퀴가 모두 가운데 파이프 위)가 −0.6 mm 로 내려가는데, 가상 모형은 이 구간을 0 으로 둔다. 강체 파이프라면 0 이어야 하는 구간이다. CNN 이 이 구간을 보고 크기를 깎았고(이 구간만 모형값으로 바꾸면 1.03 → 1.64), 규칙은 이음부 양옆만 보므로 영향이 없었다. 왜 내려가는지는 확인하지 못하였다. 하중에 의한 파이프 휨일 가능성이 있어 대차를 파이프 가운데 세우고 다이얼 게이지로 재 보는 실험을 남긴다.

**처짐 크기.** 실측 처짐 신호 크기(이음부 최대 0.36~0.54 mm)는 모형의 2 mm 처짐(0.38)과 같다. 즉 모형은 맞다. 그런데 규칙의 처짐 상수는 받침 한 개 침하 기준이라 논문 배치 3(받침 두 개 침하)의 깨끗한 신호엔 0.96 을 준다. 규칙이 실측 처짐을 "위험"으로 맞춘 것은 좌측 레일 800~1000 mm 의 다시 놓임 변형(−0.37)이 더해진 덕이었다. 바탕에는 500 mm 현측정이 긴 변형을 작게 보는 성질이 있다(Ágh 2021). 허용 한계 1.0 mm 처짐은 0.19 mm 신호가 되어 다시 놓임 0.3 mm 아래에 묻힌다. 1회 주행으로는 못 잡고 3회 평균이 필요한 이유다.

## 2차 — 고친 것

| 방법 | 바꾼 점 |
|---|---|
| C2 CNN 구간 제한 | 결함 정보가 물리적으로 없는 구간(300~340, 860~940, 1460~1500 mm)을 입력에서 0 으로 지움. 실측 정상 안 씀 |
| C3 CNN 구간 제한 + 실측 정상 적응 | C2 에 더해, 실측 정상 4회를 배경으로 섞고 "정상이면 0" 손실을 더함. 5회 교차검증, 5개 모델 평균 |
| 센서 어긋남 검사 | 한쪽 신호가 이음부를 지나는데 부호가 안 바뀌고 0.7 mm 이상 유지 → "센서 점검". 학습 없음 |

| 방법 | 가상 검증 | 실측 종류 | 실측 단계 | 센서 검사 뒤 | 단차 크기 | 처짐 크기 | 정상 회차 최대 |
|---|---|---|---|---|---|---|---|
| A 규칙 | - | 12/18 | 17/18 | 18/18 | 1.87 ± 0.02 | 1.37 ± 0.10 | 0.03 / 0.13 |
| C1 CNN | 81 % / 82 % | 17/18 | 15/18 | 16/18 | 1.39 ± 0.11 | 1.24 ± 0.40 | 0.04 / 0.15 |
| C2 구간 제한 | 81 % / 82 % | 17/18 | 13/18 | 14/18 | 1.85 ± 0.03 | 0.99 ± 0.37 | 0.06 / 0.15 |
| **C3 구간 제한 + 실측 정상 적응** | 79 % / 81 % | **17/18** | **17/18** | **18/18** | **1.98 ± 0.03** | 1.56 ± 0.44 | 0.04 / 0.17 |

3회 평균 판정(센서 점검 회차 31차 제외): A 종류 30/50·단계 50/50, C1 50/50·48/50, C2 50/50·38/50, **C3 50/50·50/50**.

센서 어긋남 검사는 18회 중 31차만 표시했다 (우측 600 부근 +1.22 mm). 31차는 앞 단계에서 우측 센서 일부 구간이 1.2 mm 어긋났다고 확인한 회차다.

읽는 법.
- 구간 제한만으로 단차 크기가 1.39 → 1.85 로 돌아왔다. 원인 추적이 맞았다는 뜻이다.
- 구간 제한만 하면 처짐은 오히려 0.99 로 내려간다. 지워진 구간에 실측의 다시 놓임 변형이 있었고, 그것이 처짐을 올려 주고 있었기 때문이다. 규칙과 같은 종류의 운이 C1 에도 있었다.
- 실측 정상 배경을 섞은 C3 가 그 운을 "배경은 결함이 아니다"로 바르게 배워 처짐 1.56, 단계 17/18 이 됐다. 가상 검증 성적은 조금 내려갔다(79 %). 실측 배경이 가상 검증보다 어려워서다.
- 모델을 고른 순서를 밝힌다. 구간 제한은 실측 단차 신호를 본 뒤 설계했다(공개). 실측 정상 적응은 1차 결과를 보고 원칙을 바꿔 넣었다. 실측 결함 주행은 어느 단계에서도 학습에 들어가지 않았다.

## 쓰는 모델

**C3.** 종류·크기 = CNN 5개 평균, 좌우 높이차·위치·쪽 = 기존 규칙, 단계 = 논문 2.3 규칙 3회 평균, 센서 어긋남 검사 먼저.

## 서버 판정 엔진에 붙임

- `rail_ai.py` — numpy 만으로 CNN 을 돌린다 (torch 불필요, 레포 requirements 에 numpy 만 있음). torch 결과와 2e-7 안에서 같음을 확인. 어떤 격자든 받아 300~1500 mm·2 mm 로 다시 얹는다.
- `rail_ai_weights.npz` — 5개 모델, 1.4 MB.
- `rail_judge_v2.py` 에 `RAIL_AI=1` 경로 추가 (기본 꺼짐). 크기만 AI 값으로 바꾸고 나머지 판정은 그대로. 센서 어긋남이면 `defect_type="sensor_check"` 로 내고 3회 평균에서 뺀다. 기준선 등록을 평균 → 중앙값으로 바꿨다(31차 같은 회차가 기준선에 섞이지 않게).
- 레포 작업 폴더에 넣었고(`rail_ai.py`, `rail_ai_weights.npz`, `rail_judge_v2.py`, `docs/ai-judge.md`), 사용자 PC 에서 numpy 2.2.6 으로 import·추정이 되는 것을 확인했다. 커밋은 하지 않았다.
- 실측 24회 서버 재생: 정상 31차 `sensor_check`·나머지 정상, 단차 2.0 위험, 처짐 3회 평균 1.4~1.6 위험, 좌우 높이차 cross_level 2.7~3.0 주의.
- 주의: 서버의 5 mm 중앙값 격자를 그대로 AI 에 넣으면 처짐이 흔들린다(20차 1.34 → 0.51). 그래서 원시 표본을 AI 격자에 직접 얹는다.

### 학습에 안 쓴 가상 주행으로 엔진째 비교 (다시 놓임 4단계 × 120배치 × 3회 = 1,440회)

| 엔진 | 종류 정답 | 3회째 단계 정답 | 주의 → 주의 | 위험 → 위험 | 정상 오경보 1회 | 정상 3회째 주의 이상 | 단차 크기 비율 | 처짐 크기 비율 |
|---|---|---|---|---|---|---|---|---|
| v2 규칙 | 75 % | 75 % | 60 % | 93 % | 18 % | 17 % | 1.03 | 1.09 |
| v2 + AI | 80 % | 82 % | 46 % | 97 % | 9 % | 8 % | 1.09 | 1.27 |

AI 를 켜면 종류·단계 정답이 5~7 %p 오르고 정상 오경보가 절반이 된다. 대신 "주의" 결함을 "위험"으로 올려 보는 일이 는다. 가상에서는 크기를 9~27 % 크게 재기 때문이다(실측에서는 반대로 처짐을 작게 잰다). 실측 정상 배경을 섞으면서 크기 눈금이 가상과 실측 사이 어딘가로 옮겨진 것으로 보이나, 실측으로 눈금을 맞추는 것은 원칙에 어긋나 하지 않았다. 센서 어긋남 검사의 가상 오표시는 0/1,440 (받침 침하 봉우리와 구분하는 평평함 조건을 넣은 뒤).

## 남은 일

1. 파이프 가운데 구간이 내려가는 원인 실험 (대차를 파이프 가운데 세우고 게이지로 측정).
2. 처짐 크기는 여전히 흔들린다(1.1~2.3). 현측정의 한계라 3회 평균이 필수. 현 길이를 늘리거나(앞뒤 바퀴 간격) 복원 방법(Chen 2024)을 보는 것이 다음 개선.
3. 좌우 높이차 4~6 mm 실험 후 AI 에 추가.
4. 대시보드·Unity 에 `sensor_check` 표시 추가 (배준호·김병서).

## 재검증 (2026-11-04 밤)

네 가지를 따로 돌렸다. 모두 통과했고, 하나는 조건이 붙는다.

| 검사 | 결과 |
|---|---|
| 1. 한 번도 안 쓴 가상 600회(씨앗 31)에서 AI 직접 비교 | 종류 58 → 76 %, 단계 68 → 79 %, 단차 오차 0.50 → 0.22, 처짐 오차 0.61 → 0.48, 정상 오경보 27 → 6 %. 3회 평균 단계 138 → 162/200 |
| 2. 같은 600회를 서버 엔진째(규칙 vs AI) | 종류 60 → 74 %, 3회째 단계 62 → 78 %, 정상 오경보 50 → 20 %, 센서 점검 오표시 0. 주의→주의는 56 % 로 같음 |
| 3. 다른 씨앗(11)으로 C3 다시 학습, 실측 18회 | 종류 17/18 (같음), 단계 15/18 (씨앗 7 은 17/18). 처짐 18차·20차가 0.76·0.96 으로 "주의". 3회 평균으로는 처짐 위험 19/20, 단차 20/20, 정상 오경보 0/10 |
| 4. 사용자 PC 의 레포 파일 그대로 실측 24회 재생 (RAIL_JUDGE=v2 RAIL_AI=1) | 컨테이너 결과와 같음. 단차 2.0 위험, 처짐 1.2~2.3 → 3회 평균 위험, 좌우 높이차 2.7~3.0 주의. 레포 시험 30개 통과 (기본 / v2 / v2+AI 세 모드 모두). 가상 모형 자체 검사 21/21 |

조건: **실측 처짐의 1회 판정은 씨앗에 따라 15~17/18 로 흔들린다.** 2 mm 처짐 신호가 0.4 mm 에 불과한 현측정 한계 때문이라 모델을 바꿔도 없어지지 않는다. 3회 평균이면 어느 씨앗에서도 19~20/20 이므로, 시스템 판정은 3회 평균을 그대로 둔다 (논문 2.3 규칙).

같이 고친 것: `rail_defect.DEFECT_LABELS` 와 대시보드 `DEFECT_LABELS`·`driveAction` 에 `sensor_check`("센서 점검", "센서 고정·배선 점검 후 다시 측정") 추가.

### 11-05 추가: 대시보드·Unity 에서 가상 주행 재생

- `POST /api/replay_virtual` 추가 (main.py). 레포 `가상주행/` 의 가상 주행 CSV(기준선 정상 6회 + 시나리오별 위험 배치 2·주의 배치 1, 각 3회)를 실측 재생과 같은 길로 엔진에 넣고 대시보드와 Unity 레일에 보낸다. 화면 제목 "가상 주행 재생 → 주행 분석 → Unity 레일".
- 이 과정에서 찾은 것 셋. (1) v2 분석기에 `store` 가 없어 `RAIL_JUDGE=v2` 에서 실측 재생 API 가 죽었다 → v1 과 같이 기준선 파일 저장·읽기 추가. (2) 센서 어긋남 검사가 3.8 mm 받침 침하를 센서 점검으로 잘못 표시 → 신호가 이음부 ±250 mm 밖까지 이어질 때만 표시하도록 조건 추가. (3) 양쪽이 같이 내려앉은 가상 주행에서 복원 높이의 좌우 차이가 다시 놓임 때문에 커져 처짐을 0 으로 지우던 것 → AI 가 양쪽 침하를 차이의 절반 이상으로 읽으면 AI 값을 믿도록 바꿈.
- (3) 뒤 학습에 안 쓴 가상 1,440회: v2+AI 종류 80 %, 3회째 단계 82 %, 위험→위험 97 %, 주의→주의 46 %, 정상 오경보 9 %. 재검증 600회: 종류 74 %, 단계 78 %, 위험 95 %, 주의 56 %, 오경보 20 %. 실측 24회는 그대로.
- 레포 시험 30개 세 모드 통과. 사용자 PC 레포에 반영하고 grep 으로 확인함 (앞서 한 번 rail_ai.py 가 옛 판으로 올라간 것을 발견해 다시 올림).

### 지금 단계의 결론

좌우 높이차(4~6 mm 실험 뒤)와 파이프 가운데 구간 원인 실험을 뒤로 미루면, 가상 모형 → 가상 데이터 → 가상 시운전 → 엔진 수정 → AI → 서버 연결까지의 한 바퀴는 여기서 끝이다. 남은 것은 팀 몫이다: 레포 커밋, 대시보드·Unity 에서 `sensor_check` 표시 확인, 서버 켜고 `RAIL_JUDGE=v2 RAIL_AI=1` 로 한 번 돌려 보기.
