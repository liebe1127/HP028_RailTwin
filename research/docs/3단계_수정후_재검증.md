# 3단계 — 판정 엔진 수정안 v2 와 수정 전/후 재검증 (2026-11-03)

팀 코드(pass_analysis.py, rail_defect.py)는 건드리지 않고, 위치 보정(PassProfile.resample)만 그대로 가져다 쓰는 별도 모듈 rail_judge_v2.py 를 만들어 같은 재생 장치로 수정 전/후를 비교했다. 코딩은 각자 하기로 했으므로 이 모듈은 "제안"이며 병합은 서버 담당이 정한다.

## 수정 내용 (rail_judge_v2.py)
- a. 분류 문턱을 허용 한계와 분리: 결함 '있음'은 한계의 절반부터 (단차·처짐 0.5, 좌우 높이차 2.5 mm) → 주의 단계 복구
- b. 템플릿을 레일 끝 높이 4개(600−, 600+, 1200−, 1200+) 기본형으로, 좌·우 따로 최소제곱 → 임의 위치·한쪽 레일 결함 크기와 위치 보고
- c. 좌우 높이차 문턱 2.5 mm(ISO 주의선), 드리프트 지표(복원 끝 높이·잔차 RMS)와 재등록 권고 플래그
- d. 감속·정지를 주행 분석 결과(rail_risk)에서 내고 진행 방향 앞 두 구간을 미리 본다. 엔코더 원시값은 직전 주행의 이음부 위치·배율로 레일 좌표로 바꿔 쓴다
- e. 판별·판정 모두 최근 3회 평균 크기로 (1회 값으로 '있음'을 정하지 않음). 잔차 RMS > 0.3 이면 '신뢰 낮음' 경고

## 실측 24회 (수정 전 → 후)
- 정상: 5/6 → 5/6 (센서 이상 회차는 둘 다 좌우 높이차로)
- 단차: 6/6 위험, 크기 1.83~1.85 → 1.94~1.97 (정답 2)
- 처짐: 6/6 위험, 1.92~1.96 → 1.93~2.01
- 좌우 높이차 구성: 전 "좌우 높이차 3.0~3.3 주의" → 후 "우 레일 1200 단차 0.7 주의(주)" + "좌우 높이차 2.5~3.5 주의" 둘 다 보고. 논문 3.2 가 확인한 0.7 mm 단차를 이제 따로 잡는다

## 가상 1,800회 (다시 놓임 0.08~0.25 포함), 수정 전 → 후

| '위험' 결함 → 위험 (3회째) | 53 % | 81 % |
| '주의' 결함 → 주의 (3회째) | 9 % | 44 % |
| 정상 레일 오경보(1회) | 67 % | 35 % |

결함 모양별 크기 비율(다시 놓임 0): 단차 파이프 전체 0.54→1.03, 이음부 끝만 0.47→1.01, 한쪽 레일만 0.26→1.03, 침하 600·1200 1.03→1.04, 받침 하나 0.55→1.00

다시 놓임 크기별 [정상 오경보(1회) / 위험 결함→위험]: 0 → 0 %/41 % → 1 %/95 %, 0.03~0.06 → 7 %/45 % → 6 %/95 %, 0.08~0.12 → 47 %/45 % → 10 %/86 %, 0.15~0.25 → 90 %/45 % → 51 %/86 %

## 남은 한계 (수정으로 안 풀린 것)
- 레일 모양이 0.15 mm 이상 바뀌면 정상 오경보 51 %, 3회 평균 뒤 주의 이상 35~50 %. 문턱을 내린 대가. 기준선 재등록 또는 레일 고정(물리)로만 풀림 → 드리프트 플래그가 그 신호
- 주의 구간(0.5~1.0) 결함은 44 %만 주의. 신호 0.2~0.4 mm 가 다시 놓임과 같은 크기라 원리적 한계
- 추가 확인 필요: 트윈의 대차 위치가 엔코더 원시값(출발점 0)인지 레일 좌표인지. 서버 결함 구간은 레일 좌표(600~1200)라 원시값이면 화면에서 약 300 mm 늦게 들어감 (김병서 확인)
