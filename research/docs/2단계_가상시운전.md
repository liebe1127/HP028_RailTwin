# 2단계 가상 시운전 결과 (2026-10-29)

서버 판정 엔진(레포 9/29 커밋, pass_analysis.py + rail_defect.py)을 한 줄도 바꾸지 않고, replay_csv.py 가 실측을 넣던 방식 그대로 가상 주행을 재생했다. 먼저 실측 24회로 논문 3.3 절의 서버 재생 결과, 즉 정상 6회를 기준선으로 등록한 뒤 결함 18회 18/18(단차 1.84, 처짐 1.9x, 좌우 3.0~3.3 주의)을 그대로 재현해 재생 장치가 맞는지 확인한 뒤 진행.

## 재생한 것
- 가상 v2 1,800회(600배치 × 3회: 정상/단차/처짐/단차+처짐, 크기 0.3~4 mm, 속도 30~100 mm/s, 엔코더 미끄러짐 좌 +1~19 %). 기준선은 가상 정상 6회.
- 다시 놓임 변화 실험: 레일 모양 변화 0 / 0.03~0.06 / 0.08~0.12 / 0.15~0.25 mm(현측정 RMS)로 120배치씩 따로 재생.

## 잘 되는 것
1. 엔코더 보정: 1,800회 전부 성공, 배율 오차 중앙값 0.09 %, 최대 0.32 %. 미끄러짐 19 %도 문제없음.
2. 속도 30~100 mm/s: 정답률 차이 없음.
3. 레일 모양이 기준선과 같으면 정상 오경보 0 %, 실험한 두 모양(가운데 파이프 전체 단차, 600·1200 처짐)은 크기 비율 0.92 / 1.03.

## 발견한 문제 (실측 24회로는 보이지 않던 것)
1. **주의 단계가 단차·처짐에서는 절대 나오지 않는다.** 분류 문턱(THRESHOLD_MM 1.0)이 허용 한계(1.0)와 같아서, 1.0 아래는 '정상', 1.0 위는 바로 '위험'. 정답이 주의인 단일 결함 22배치 전부 '정상'. 실측은 2 mm(위험)와 0(정상)뿐이라 드러나지 않았다.
2. **템플릿이 실험 구성 두 가지에 고정.** 1200 이후 파이프만 올라간 단차 0.50, 이음부 한쪽 끝만 0.47, 한쪽 레일만 0.26, 받침 하나만 침하 0.55 (서버 크기/실제). 위치도 항상 600~1200 으로 보고. 실험한 모양이 아니면 크기가 반으로 줄어 놓치거나 단계가 내려간다.
3. **기준선 민감도.** 기준선 등록 후 레일 모양이 바뀌면 정상 레일 오경보(1회): 0 → 7 % (0.03~0.06) → 47 % (0.08~0.12) → 90 % (0.15~0.25). 대부분 '좌우 높이차'. 좌우 높이차 판별 문턱 1 mm 가 실제 모양 변화 약 0.1 mm 에 해당하기 때문(템플릿 봉우리 0.42 mm/2 mm). 3회 평균해도 0.15 이상이면 40 %가 주의 이상.
4. **감속·정지 신호가 주행 분석과 따로 논다.** snapshot 의 motion 은 옛 구간 규칙(_judge_open_segment)에서 나오고 pass_result 와 연결돼 있지 않다. 1,200회 중 'slow' 416회, 'stop' 0회, 처음 나온 위치 중앙값 989 mm(결함 구간에 들어간 뒤). 트윈 색칠은 pass_result(rail_risk) 기준이라 화면과 신호가 다를 수 있음 — Unity 가 어느 필드로 감속을 정하는지 확인 필요(김병서).

## 서버 담당에게 전할 수정 후보
a. 분류 문턱을 한계의 절반(0.5 mm)으로 내리거나 분류와 단계를 분리 → 주의 단계 복구.
b. 템플릿을 레일 끝 높이 4개(600−, 600+, 1200−, 1200+) 기본형으로 바꾸고 좌·우 따로 맞추기 → 임의 위치·한쪽 결함 크기가 맞음 (sim2real.py 의 4-높이 복원이 그 예).
c. 좌우 높이차 판별 문턱을 ISO 주의선 2.5 mm 로, 기준선 드리프트 감시(정상 구간 잔차 RMS) 추가.
d. motion 을 pass_result(rail_risk) 와 연결하고, 다음 구간이 주의·위험이면 미리 감속·정지.
